# YoVouch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add YoVouch to YoCard: signed, withdrawable vouch lines recorded with a rotating code at the end of a job, shown in a new tier on the card, and carried to an employer in a six-line Reply by Voice.

**Architecture:** New modules under `server/card/` hold the rotating code, the vouch store, the line and label builders, the flags, the reply parser and drafter, and the SMS and WhatsApp handlers; `buildVouchSystem` in `server/card/vouch-system.js` wires them from `store.dir`. `createCardRouter` in `routes.js` builds that system and delegates `/my/`, `/s/`, `/v/`, `/a/`, `/o/`, `/r/`, `/api/vouch/`, `/api/request/`, `/api/reply/`, `/api/refer/`, `/api/sms/`, `/api/wa/`, `/api/sim/`, `/demo/` and `/qr-browser.js` to a vouch router and a reply router. Every page is server-rendered HTML that works without JavaScript, and the simulated gateways drive the same handlers a real gateway would.

**Tech Stack:** Node 20+ built-ins only (`node:crypto`, `node:fs`, `node:http`, `node:vm` in tests, `fetch`, `node:test`); vanilla HTML/CSS/JS; the existing ES256 signer, QR encoder, grounding validators and chat providers; an OpenAI-compatible or Azure `/audio/transcriptions` endpoint.

## Global Constraints

- Node `>=20` (package.json `engines`). Node built-ins only. No npm packages, no vendored code.
- Size: card page HTML at most 10240 bytes after the line fallback. Vouch list page at most 10240 bytes per page of 20. Scan, chips, disclosure, bind, read-back, done and withdraw pages at most 4096 bytes each. Worker code page at most 13312 bytes without JavaScript.
- Code time step 90 seconds, `counter = floor(unixSeconds / 90)`. Scan page window `{now-1, now}`. SMS and IVR window `{now-2, now-1, now}`. Never `now+1`. Batch of 10 steps.
- Spoken code: RFC 4226 dynamic truncation over HMAC-SHA256, modulo 10^6, zero-padded, shown `483 201`. QR tag: the first 8 characters (40 bits) of HMAC-SHA256(secret, `"qr:" + counter`) in the store alphabet.
- Alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` for every id and short code. Vouch, request, post and reply ids: 10 characters. Card code, session code, link code and SMS withdraw secret: 6 characters. `smsId`: 5 digits. `cardToken`: 16 hex. `vouchToken` and `referToken`: 24 hex. Web withdraw secret: 16 hex. `vouch.secret`: 20 random bytes as hex.
- Spoken lock: 5 wrong codes per card in 10 minutes; the sixth locks the spoken path for 10 minutes; the QR path stays open. 10 wrong codes per sender per hour, then that sender gets no reply for an hour.
- Honesty strings verbatim on every new page: `Not operated by Yoma or UNICEF` and `signed by YoCard, not by Yoma` (both inside the existing footer `Student prototype. Not operated by Yoma or UNICEF. Record signed by YoCard, not by Yoma.`) and `Who can see this: anyone with the link`. Unchanged: `Never pay before the work is done`, `Phone confirmed by Yoma (not an ID check)`, `Phone not confirmed by Yoma`, `Stated by <First name>, not checked`, `Confirmed from Yoma`, `This image is not proof, open the link`.
- "Not by Yoma" rule: every vouch tier label contains `confirmed by them, not by Yoma`. A flag label is appended after it with ` · ` (spec 4.2), so only an unflagged label ends with it. No vouch string contains `in person`, `Recorded in person`, `Vouched in person`, `in the same place`, `co-presence` or `You are with`. The only `in person` string is `Show your ID in person only`. No `verified by Yoma` anywhere. No green outside the Yoma tier except the existing Check now button.
- Grounding validators reused, never forked: `quoteInSource`, `noInventedNumbers`, `noBannedClaims`, `dedupe` from `server/validate.js`; `namesOrganisation`, `BANNED_CONFIRM_PHRASE`, `PRICE`, `AREA`, `findArea` exported from `server/card/draft.js`. New length checks count code points: 120 (voucher words, reply lines 1 to 5) and 160 (organisation statement). `lengthOk` stays at 1 to 180.
- No count on any public surface: not the identity line, the share image, the list page or `All vouches`. No `0` completions anywhere: the item is omitted.
- `hireAgain` and `workAgain` are `yes` or `not stated`. `howOften` is `once`, `a few times`, `regularly` or `not stated`. There is no "no".
- The owner secret is accepted only by `POST /api/card/:id/withdraw` and `POST /api/card/:id/rotate-token`. Every other worker action takes the card token.
- Demo-only routes: `POST /api/sim/sms`, `POST /api/sim/wa`, `/demo/phone`, `/demo/ivr`, `/demo/inbox` and `/demo/beat3` exist only when `YOVOUCH_SIM=1`. `/thread.html` and `/thread.js` are plain static files (spec 9.5) that only work against `/api/sim/wa`. `POST /api/sms/webhook` and `POST /api/wa/webhook` exist only when `YOVOUCH_GATEWAY_SECRET` is set, and answer 403 unless header `x-yovouch-gateway-secret` matches it in a constant-time compare. `POST /api/vouch/:vouchToken/otp` exists only when neither is set.
- Private responses: every page or response that carries a live code, a card token, a vouch session or a withdraw secret sends `Referrer-Policy: no-referrer` and `Cache-Control: no-store`, loads no third-party asset and uses `shell({fonts:false})`.
- No outbound message without an inbound one from the same number in the last 15 minutes (`outbox.send` throws `unsolicited`). Nothing is ever sent to a typed number.
- Phone numbers: only `HMAC-SHA256(hashKey, E.164)` and the last 3 digits are stored. A local-format sender with no card context is read with `config.yovouch.smsCountry` (default `South Africa`). No IP address is stored. The model never receives names, phone numbers, card ids or voucher numbers.
- Template mode (no live provider): every flow page and every message list carries `Sample mode: template extraction, no model call`.
- Events in `events.jsonl` carry ids, channel and timestamps only, plus `demo: true` for cards built from a sample persona.
- Existing suites stay green. Commit per task, message ending `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
